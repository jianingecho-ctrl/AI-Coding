# 独立版使用指南 · 0.9.2

## 拆分后的行为

海洋版和甄嬛传版各有固定控制台、人物、启动入口、安装身份和本地数据。打开即进入本版，没有主题切换，不需要在旧版顶部切换或修改主题参数。

| 项目 | 海洋版 | 甄嬛传版 |
| --- | --- | --- |
| 下载 | [海洋源码 ZIP](https://github.com/jianingecho-ctrl/AI-Coding/archive/refs/tags/ocean-v0.9.2.zip) | [甄嬛传源码 ZIP](https://github.com/jianingecho-ctrl/AI-Coding/archive/refs/tags/palace-v0.9.2.zip) |
| 启动脚本 | 启动海洋版.command | 启动甄嬛传版.command |
| 版本标识 | 海洋独立版 / 0.9.2 | 甄嬛传独立版 / 0.9.2 |
| 应用名称 | 职场小判官·海洋版 | 职场小判官·甄嬛传版 |
| 配色 | 海蓝、浪花、气泡 | 朱红、鎏金、素纸、窗棂 |
| 待机默认 | 白衣红裤蓝鱼 | 甄嬛 |

人物列表和保存接口只允许本版内置人物；历史恢复使用本版人物。自定义上传进入本版素材库，不自动出现在另一版。每版分别保存联系人、人物、消息、回复、计数、素材、尺寸、声音、AI 和密钥。修改、清空、退出一版不影响另一版，两版可同时运行。

## 首次启动

1. 退出正在运行的旧版本，保留旧文件夹，不覆盖。
2. 下载需要的独立源码包，解压到新文件夹。
3. 安装 Node.js 24 LTS 后双击对应脚本，等待依赖安装和构建。
4. 确认本版控制台与 0.9.2 版本标识，再发送模拟消息。

两版都可使用 npm ci、npm run build、npm start；在哪个文件夹运行，就打开那个固定版本。完整步骤见 [Mac 教程](Mac使用教程.md)。

## 数据目录

```text
~/Library/Application Support/workplace-little-judge-ocean/
~/Library/Application Support/workplace-little-judge-palace/
```

各自包含：

```text
judge-state.json  联系人、配置、消息、回复、次数、素材索引
assets/          本版素材副本
ai-key.enc       本版系统加密 API Key
session/         本版会话和缓存
```

源码运行与打包安装使用相同本版目录。备份前退出对应应用，再复制整个目录。不要把一版目录覆盖到另一版。

## 旧 0.7.0 数据

旧版把主题和数据混在同一个应用里，无法可靠分成两份名单。甄嬛版从新名单开始，不自动导入旧共享数据。

海洋版只在本版没有 judge-state.json，且旧目录配置有效、最后使用海洋主题时，尝试一次性复制。检查的旧目录为同级 workplace-little-judge/ 和 职场小判官/。

符合条件时复制联系人、历史、回复、计数和素材；夹杂的宫廷内置人物恢复为海洋默认。原目录保持原样。复制后关闭 AI，不复制旧密钥，需要在本版重新输入并主动启用。

旧目录最后是宫廷主题、配置损坏、目录名不同或本版已有配置时，不自动复制。旧数据没有删除，原目录可备份。此后两版各自保存，不同步。

## AI 和消息范围

0.9.2 保留模拟消息，并新增可见通知 OCR 接入。真实通知始终使用本机规则，默认人工确认、重启暂停；使用步骤见 [飞书通知教程](飞书通知使用教程.md)。通知设置与识别运行状态也属于各自版本。模拟消息默认本地规则，本机 Ollama、在线服务分别在各自设置中启用。

在线 AI 只传输当前消息正文、模型参数、摘要提示到配置服务；名单、历史、回复和素材不上传。结果需核对原文，失败提示并降级。模拟回复不发送到飞书，趣味互动不通知联系人。

## Mac 验收

同时打开两版，在海洋版改联系人、发送消息并肘击，甄嬛名单和计数应不变。清空海洋历史、退出海洋版，甄嬛应继续运行。分别重启，自己的记录应恢复。

云端自动测试已覆盖上述行为，实际拖动、音效、Keychain、跨 Spaces 和安装仍需本机确认。
